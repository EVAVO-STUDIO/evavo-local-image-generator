================================================================================
                 SAFE LOCAL COMMIT / PUSH TO MAIN
================================================================================

This file is retained for old bookmarks. The historical instructions that used
blind `git add -A`, stale "production ready" commit text, manual lock deletion,
archive extraction, or repository reinitialization are retired.

Preferred local workflow from the repository root:

  python safe_main_git.py --message "describe the actual completed change"

Or use the PowerShell compatibility shim:

  .\COMMIT-UPGRADE.ps1 -Message "describe the actual completed change"

Dry-run the safety checks without staging/committing:

  python safe_main_git.py --dry-run

Create a verified commit but do not push:

  python safe_main_git.py --no-push --message "describe the actual completed change"

The helper enforces:

  - active Git worktree must be this repository;
  - current branch must be `main`;
  - `origin/main` is fetched and divergence is checked;
  - local main must not be behind or diverged;
  - runtime/generated output paths are rejected from generic commits;
  - full EVAVO verification runs before committing by default;
  - no Git lock deletion;
  - no `.git` deletion/reinitialization;
  - no Git identity rewriting;
  - no remote creation/replacement;
  - no force push;
  - normal push only to `origin main`;
  - the pushed SHA is fetched and verified after success.

If the helper says local main is behind origin/main, update safely first:

  git pull --ff-only origin main

If history has diverged, stop and reconcile it deliberately. Do not use a force
push or delete/recreate `.git` as a recovery method.
